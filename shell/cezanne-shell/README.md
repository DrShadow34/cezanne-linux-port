# cezanne-shell

The phone shell on [niri](https://github.com/niri-wm/niri), in place of GNOME
Shell and GDM (2026-11-13). One [Quickshell](https://quickshell.org) process
(Qt Quick) draws everything around niri's windows. squeekboard is the
on-screen keyboard for apps, and swayidle handles idle and sleep. The login
screen is greetd with the same Quickshell components in a separate niri
instance.

## What it does

| Part | File | Notes |
|---|---|---|
| Panel | `Panel.qml` | Transparent top bar. Left: workspace dots; tap them for niri's overview. Middle: the clock, with a dot when there are notifications; tap it for the calendar. Right: Wi-Fi, Bluetooth, do-not-disturb, Caffeine, battery %; tap them for the quick menu. |
| Quick menu | `QuickMenu.qml` | Battery (while charging: the type as bolts, one for 5 V, two for fast 9 V PD or QC, three in yellow for the charge pump, and the power into the battery, every 3 s from `cezanne-aod-ctl charge`), screenshot, Settings, lock and power buttons; brightness and volume (PipeWire) sliders; "A" next to brightness is automatic brightness (`System.qml`, cezanne-autobrightness's: the light sensor through monitor-sensor, a lux -> nits curve in log(lux), brighten after 0.3 s, dim after 2 s, smooth ramps; the slider is then a gain on the curve, x1/4 .. x4, middle = the curve; GNOME's ambient-enabled key, which cezanne-base's sunlight-boost also reads for the panel's HBM above 1000 lux; not in the AOD). The backlight is written through one open shell (video group, cezanne-base's udev rule), else logind's SetBrightness. Toggles: Wi-Fi with its network list and passwords (NetworkManager), Bluetooth with paired devices, Auto Rotate, Dark Style (GNOME's color-scheme, which GTK apps follow), Do Not Disturb, Caffeine, Show Taps, Flashlight (the rear flash LEDs; Low / Medium / High), Airplane Mode (rfkill blocks every radio, NetworkManager's WWAN off), NFC (`Nfc.qml`: the neard field only while unlocked, unpowered otherwise; tag notifications through notify-send with Open / Copy; the GNOME extension's dconf key), DC Dimming and Colors (the panel's dc_dimming / color_mode: Vivid, Natural, Standard, Saturated; kept in `~/.config/cezanne/` and applied at start, as cezanne-dc-dimming did). The card scrolls when it is taller than the screen (landscape). Wi-Fi and Bluetooth lists open right under their row. Opens over fullscreen apps too (overlay layer). |
| Calendar | `CalendarView.qml` | Date, month grid (Monday first, tap the title for today), notification list with Clear. |
| Notifications | `Notifications.qml`, `NotificationCard.qml` | The org.freedesktop.Notifications server. Banners show below the panel, but not with Do Not Disturb or over fullscreen windows, except critical ones. Tap runs the default action. |
| Launcher | `Launcher.qml` | Full-screen app grid: 4 columns in portrait, 8 in landscape, its shade over the top bar too. It holds the keyboard exclusively while open (as do the menus), so the on-screen keyboard types into it, never into the window below. Tapping the search field brings up the keyboard. Long press pins an app to the dock. |
| Dock | `Dock.qml` | Pinned apps, then running ones, then the app grid button. Shown on an empty workspace, in the overview and in the launcher; while a window covers the screen, a swipe up from the bottom edge shows it for 4 s (like dash-to-dock's intellihide). Tapping a running app focuses it, again cycles its windows; long press: Close, Pin / Unpin. |
| Lock screen | `LockScreen.qml`, `PasswordPrompt.qml`, `Keyboard.qml` | ext-session-lock, after a 0.26 s fade to black: clock, date, battery, notification count over the wallpaper, blurred once with ffmpeg into the cache (a live full-screen blur cost effect buffers); swipe up or tap for the password. It has its own keyboard: niri draws only lock surfaces while locked, so squeekboard can't show. PAM service `cezanne-shell` (a cancelled prompt doesn't count for faillock).. Fingerprint (with cezanne-fp): a second PAM conversation (`/etc/pam.d/cezanne-shell-fingerprint`, pam_fprintd on cezanne-fpd) runs while the lock screen shows, not in the AOD and not while the password keyboard is up; the service watches the sensor spot itself and publishes its state (org.cezanne.Fod State on the system bus, followed with `gdbus monitor`): an icon over the sensor while it waits; on a press the screen dims, a white disc lights the finger and the panel goes to FOD HBM once that frame is out (the service's cue to capture), back after the press (3 s at most). After 5 failed tries only the password, until the next wake. From the password page back to the clock page (and the fingerprint): the "Use fingerprint" button above the field ("Back" when it is not in use), a swipe down above the keyboard, or Escape. The lock screen stays portrait (`Rotation.qml`), where the spot lines up with the sensor. |
| Always-on display | `Aod.qml`, `bin/cezanne-aod-ctl` | Ported from the cezanne-aod extension, same mechanism. Entering: lock, then the lock surface's AOD view fades to black (350 ms), the panel's doze (level 1, or 2 above 50 lux, or the Power app's setting) switches the brightness while the screen is black, then the clock fades in already dimmed (400 ms, at a spot that moves every minute, 5% off the sides, 20% off top and bottom), the frame out, the RTC armed one second into the next minute, then sleep through /sys/power/state, not logind. Deep sleep on battery; s2idle with a cable in, or for a minute after a refused deep attempt. On wake, by `/sys/power/pm_wakeup_irq`: the PMIC (power key, charger) wakes to the lock screen, the RTC alarm moves the clock and sleeps again, anything else (Wi-Fi) rests 1 s and sleeps again. A sleep block inhibitor or Caffeine keeps it awake in the AOD. Wi-Fi and Bluetooth go off in standby per the Power app's settings and come back on. It is entered by the power key (niri binds XF86PowerOff to `cezanne-shell-ctl aod power`; while the AOD is on the shell holds logind's handle-power-key inhibitor, so the press that woke the phone is ignored for 1.5 s), by swayidle's 60 s idle (`aod idle`), by 20 s idle while locked, and by the power menu's Suspend. With the AOD off, these lock and suspend through logind. Settings: org.cezanne.power (cezanne-power app), plus an Always-on Display toggle in the quick menu. |
| Rotation | `Rotation.qml` | iio-sensor-proxy (`monitor-sensor --accel`) to `niri msg output DSI-1 transform`. Not while locked, nor with Auto Rotate off. |
| Polkit agent | `PolkitDialog.qml` | The request and a password prompt with the shell's keyboard. |
| Volume OSD | `Osd.qml` | Shown on volume key presses (niri binds them to wpctl). |
| Touch | `Touch.qml`, `cezanne-touch.c` | niri has no touchscreen gestures. cezanne-touch (C) reads the touchscreen beside niri, without a grab. Three-finger swipes: up opens the overview, up again the app grid, and closes an open menu; down opens the quick menu, or closes the overview; left and right switch to the next or previous app (niri's columns), and past the last one go to the empty workspace (home) and back. Show Taps (quick menu, on by default) draws a spot under every finger on an overlay that is only up while fingers are down. A swipe in from the left or right edge is "back": it hides the on-screen keyboard, closes a menu, the launcher or the overview, and otherwise sends Alt+Left to the app (wtype). |
| Notification light | `NotificationLight.qml` | Ported from cezanne-notification-led, through feedbackd (`fbcli`): a new notification vibrates (notification-new-generic with the app's ID); the camera's light fades in and out while there are unread notifications (since the last unlock or the last look at the calendar's list, not dismissed) in the colour of the newest one's app; else on the charger red while charging, green when charged or held at the charge limit. Do Not Disturb suppresses both; low-urgency and transient notifications don't count. The LED colours are events of a generated feedbackd theme (`~/.config/feedbackd/themes/cezanne.json`); settings are the GNOME extension's dconf keys (`/org/gnome/shell/extensions/cezanne-notification-led/`: colour, app colours, vibrate, battery light, charged percentage). |
| USB dialog | `Usb.qml`, `UsbDialog.qml` | Ported from the cezanne-usb extension, on cezanne-usbd (org.cezanne.Usb, system bus, read with busctl's JSON on every change gdbus monitor sees): a computer (not a charger) on the USB-C port opens "Use USB for" (Video stream with its sources page, Data storage, Developer network, Charge only); dismissed means charge only. Locked or fullscreen: charge only and a notification with the other choices. While connected a resident low-urgency notification shows the mode and opens the dialog (notify-send to the shell's own server). Stream mode starts cezanne-usb-stream.service; while the screen streams the shell holds its idle inhibitor. IPC `usb dialog modes|sources`, `usb setMode MODE SOURCE`. |
| Screenshots / screencasts | `Screenshot.qml`, `cezanne-screencast.c` | GNOME's screenshot UI: from the quick menu's button or Print (Ctrl+Print / Alt+Print stay niri's quick ones). The screen is captured first (grim) and shown frozen; Selection (drag a rectangle; corners resize, inside moves; kept for the next time), Screen or Window (the active workspace's windows by title: niri gives no window positions), Screenshot or Screencast, the capture button. Screenshots: the frozen frame cut out (ffmpeg) or the window through niri (`screenshot-window --id --path`), into `~/Pictures/Screenshots` and the clipboard (wl-copy), a notification (open / Show in Files). Screencasts: `cezanne-screencast` (C) on niri's org.gnome.Mutter.ScreenCast (RecordMonitor / RecordWindow), GNOME's VA-API pipeline (vapostproc, vah264enc CQP 26 on cezanne-venc, zero copy) else openh264; a selection is crop meta that vapostproc gives the VA driver as the source region; `~/Videos/Screencasts`; a red timer pill in the panel stops it, the phone does not idle meanwhile. niri's stream repeats one PTS on every frame: the recorder makes the arrival time the PTS. |
| Caffeine | `ShellState.qml`, `shell.qml` | Quick menu toggle, with a cup in the panel while on: an idle inhibitor, so no idle blank, lock or sleep. The power key still sleeps. |
| Games | `shell.qml` | A fullscreen window hides the panel, dock and banners and holds an idle inhibitor (cezanne-game-awake did this in GNOME). |
| Login | `greeter.qml`, `niri/greeter.kdl` | greetd runs niri as the greeter user (`/etc/greetd/cezanne.toml`). The greeter offers the user who last logged in, else the newest account (tap the name to switch), with a password prompt and restart / power off. It starts `niri-session` and quits; niri quits with it. PAM `cezanne-greetd` unlocks the keyring. |
| Idle | `cezanne-idle.service` | swayidle: 60 s without input runs `cezanne-shell-ctl aod idle` (lock, then the AOD, or a blanked logind suspend with the AOD off). Before any logind sleep it waits for the lock screen (`cezanne-shell-ctl lock-wait`). |

Services start on niri's `graphical-session.target` (`ConditionEnvironment=XDG_CURRENT_DESKTOP=niri`):
- `cezanne-shell` (`qs -p /usr/share/cezanne-shell/shell.qml`, `QS_ICON_THEME=Adwaita`);
- `cezanne-osk` (squeekboard, with GNOME's screen-keyboard setting on);
- `cezanne-idle`;
- `cezanne-geoclue-agent` (geoclue's demo agent; GNOME Shell was the agent before).

The shell does not reload itself when its QML changes (`settings.watchFiles: false`): Quickshell's live reload let go of the session lock for a moment. A new version starts with the shell (`systemctl --user restart cezanne-shell`, safe while locked).

niri's system config is `/etc/niri/config.kdl`; a user's `~/.config/niri/config.kdl` replaces it as a whole.

IPC: `cezanne-shell-ctl TARGET FUNCTION [ARGS]`:
- `launcher toggle|open|close`, `launcher search TEXT` (opens it with TEXT in the search field);
- `popup toggle quick|calendar|power`, `popup quick wifi|bt`, `popup close`;
- `lock lock|isLocked|prompt`, and `lock-wait`;
- `aod power|idle`;
- `caffeine get|set true|false`;
- `usb dialog modes|sources`, `usb setMode MODE SOURCE`;
- `screenshot open|stop`.

niri binds Mod+A to the launcher and Mod+L to lock, for when a keyboard is attached.

State (rotation lock, Do Not Disturb, pinned apps, keyboard page) is kept in `~/.local/state/quickshell/by-shell/<id>/state.json`.

## Not ported from the GNOME extensions yet

Missing from the extensions:
- fingerprint enrollment (cezanne-fpd has none yet; the prints are MIUI's);

Two GNOME features have no niri equivalent: night light (niri has no gamma control) and GNOME's screen recorder. Screencasts go through xdg-desktop-portal-gnome, which niri serves.

## Testing without the screen

`test/sandbox.sh DIR STEPS` runs on the phone as the desktop user, inside `dbus-run-session`. It starts niri nested in a headless cage at 1080x2400 (`cage`, `wlr-randr`, `grim`), runs the shell from DIR, follows the steps (`sleep`, `shot NAME`, `ipc TARGET FUNC ARGS`, `niri ACTION`, `run CMD`) and writes the screenshots to `DIR/out/shots`. `QML=greeter.qml` runs the login screen instead. The sandbox points the AOD at `test/aod-ctl-dummy` (`CEZANNE_AOD_CTL`), which only logs: no doze, RTC alarm or sleep from a test (its charging state is `CEZANNE_DUMMY_CHARGE`, default `direct 21400`). Nor does it touch the fingerprint sensor or the panel's FOD HBM: no fingerprint PAM conversation (`CEZANNE_FP_PAM=off`), a State timeline from `test/fod-dummy` (`CEZANNE_FOD_MONITOR`), a file for hbm (`CEZANNE_HBM`, `test/fod.steps`); the panel's DC dimming / colour scheme, the saved choices and the NFC adapter are left alone too (`CEZANNE_PANEL`, `CEZANNE_CONFIG`, `CEZANNE_NFC=off`), a backlight of its own (`CEZANNE_BACKLIGHT`), the USB port's mode read but never set (`CEZANNE_USB=off`, `test/usb.steps`), screenshots / screencasts into `out/` (`CEZANNE_PICTURES`, `CEZANNE_VIDEOS`, `test/shot.steps`; the nested niri cannot screencast: no GBM device, recordings are tested on the phone), an fbcli that only logs (`test/fbcli-dummy`, `CEZANNE_FBCLI`, `test/led.steps`: no light, vibration or feedbackd theme change) and a light timeline (`test/light-dummy`, `CEZANNE_LIGHT_MONITOR`: iio-sensor-proxy only lets the active session claim the sensor); `CEZANNE_AUTO_BRIGHTNESS=1` turns automatic brightness on without the user's setting (`test/auto.steps`). It keeps its own lock state (`CEZANNE_LOCK_FILE`): the session's runtime lock file would lock the sandbox, and a sandbox unlock would mark the session unlocked. The steps files used so far are `test/basic.steps`, `test/more.steps`, `test/charge.steps` and `test/focus.steps`; the last types with `wtype` into `test/typetarget.qml`, a stand-in window that logs what reaches it (never a real app: the sandbox shares the home directory, so an app reopens the user's documents).
